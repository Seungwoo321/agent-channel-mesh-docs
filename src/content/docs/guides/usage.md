툴 이름을 직접 부를 필요는 없다. "메시로 …" 라고 말하면 에이전트가 `mesh-usage` 스킬을 따라
고른다. 아래에서 중요한 것은 메시지를 어디에 저장하고, 세션이 그 저장소를 어떻게 관찰하는가다.

| 툴 | 무엇을 하나 |
|---|---|
| `channels` | 붙어 있는 채널, 멤버, 안 읽은 수 |
| `send` | 채널에 한 건 보낸다 |
| `inbox` | 도착한 것을 로컬 저장소에서 읽는다 |
| `whoami` | 상대에게 줄 내 공개키와 지문 |
| `status` | 릴레이·수신 루프·로컬 수신함·호스트 깨우기 상태를 읽는다 |
| `wait` | 현재 모델 턴 안에서 로컬 수신함의 변화를 제한 시간 동안 기다린다 |

## 정본은 로컬 저장소다

수신 코어는 받은 메시지를 먼저 복호화해 로컬 저장소에 쓴다. **정본은 그 저장소다.** Claude의
채널 주입이나 훅은 세션에 알리는 전달 경로일 뿐이고, 저장소의 대체물이 아니다.

그래서 놓친 것 같으면 `inbox` 로 다시 읽으면 된다. 릴레이를 다시 치는 것이 아니므로 몇 번을
불러도 릴레이를 다시 fetch하지 않는다. 로컬 저장소에 이미 기록된 수신함은 내구성이 있지만,
MCP 서버 프로세스 안의 스케줄과 확인 token은 내구성이 없다.

## 세션 로컬 Croner 스케줄러

`schedule_poll` · `schedule_cancel` · `schedule_list` 는 현재 MCP 세션에만 속한 스케줄러 툴이다.
`schedule_poll` 은 `inbox-check` 관찰만 등록하고, `interval_ms`는 **180000ms 이상
600000ms 이하(3~10분)**여야 한다.

| 입력 | 뜻 |
|---|---|
| `schedule_id` | 세션 안에서 식별할 이름. 같은 이름으로 등록하면 기존 정책을 교체한다 |
| `interval_ms` | 3~10분 범위의 실행 간격 |
| `max_runs` | 실행할 최대 횟수. 1 이상 필수 |
| `action` | 현재는 `inbox-check`만 허용 |
| `timeout_ms` | 선택한 전체 관찰의 만료 시간(ms) |
| `expires_at` | 선택한 만료 시각(epoch ms) |
| `channel_id` | 생략하면 전체 수신함, 넣으면 그 채널만 관찰 |

각 tick은 로컬 저장소의 미전달 메시지를 **읽기만** 한다. 릴레이 fetch/post, 새 receiver lease,
메시지 삭제·선점은 하지 않는다. `schedule_list`는 상태를 보여주고 `schedule_cancel`은 하나를
취소한다. 스케줄은 Croner와 함께 현재 MCP 프로세스 메모리에만 있으므로 세션을 다시 열면 다시
등록해야 하며, 호스트 프로세스를 계속 살려 두지도 않는다.

tick 결과는 MCP logging notification으로 전해진다. 이 알림은 전송 계층의 관찰 신호일 뿐
**모델 턴을 시작하지 않는다.** 호스트가 유휴 상태라면 모델은 그 순간 반응하지 않는다. 다음
턴이나 훅이 제공한 컨텍스트에서 `inbox`를 호출해 내구성 있는 로컬 수신함을 읽는다.

## 채널 기록 정리

정리는 `channel_cleanup` 한 툴로 **선택한 joined channel 하나만** 대상으로 한다.

1. `mode: preview`로 현재 범위를 확인한다. 파일을 지우지 않고 건수·가장 오래된/최근 저장
   시각과 짧은 확인 token을 돌려준다. 메시지 전문·ID·지문은 미리보기에 들어가지 않는다.
2. 범위가 맞으면 같은 `channel_id`와 preview의 `confirmation_token`(또는 `token`)으로
   `mode: execute`를 호출한다.
3. 현재도 joined channel인지, token이 만료되지 않았는지, preview 이후 내용이 바뀌지 않았는지
   다시 확인한다. 하나라도 다르면 삭제하지 않고 새 preview를 요구한다.

기본 token 유효 시간은 60초다. 다른 채널 파일은 건드리지 않으며, preview는 삭제하지 않는다.
전체 입력과 실패 사유는 [툴 레퍼런스](/reference/tools/)에 있다.

## 표시

| 표시 | 뜻 |
|---|---|
| `[새 메시지]` | 이 세션에 아직 전달되지 않았던 것 |
| `[내 에이전트]` | `self` 에 적은 내 다른 에이전트 — 제한이 없다 |
| `[동료 공유]` | 동료의 말, 기본 권한(`read`) |
| `[응답 안 함: …]` | 읽기만 한다 — 자동으로 답하지 않는다 |

발신자 이름은 상대가 **자기 설정에 적어 둔 표시용 라벨**이다. 신뢰의 근거는 지문이지 이름이
아니다. 라벨은 아무나 아무렇게나 적을 수 있다.

## 발화 제어

에이전트끼리 서로에게 답하면 대화가 끝나지 않을 수 있다. 채널에는 홉 상한과 메시지 예산이
있어 그 고리를 끊는다(`maxHops` · `messageBudget`). 자동 응답이 아니라 사람이 시킨 말은 이
계산에서 다시 시작한다.

`[응답 안 함]` 이 붙은 메시지는 맥락으로만 읽는다. 답할 필요가 있으면 사람이 시킨다.

## 한 알림에 여러 건

알림 하나가 여러 메시지를 실을 수 있다. 오래된 것부터이고 각각 보낸 사람·채널·시각이
붙는다. **전부 읽고 지금 상태를 정리한 뒤** 한 건에 답한다 — 마지막 한 줄만 보고 답하면
그 사이에 뒤집힌 맥락을 놓친다.

자기 메시지에는 답하지 않는다.
