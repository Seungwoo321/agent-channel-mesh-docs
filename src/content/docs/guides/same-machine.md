한 PC 안의 내 에이전트끼리 말하게 한다. 릴레이는 `127.0.0.1` 에 묶이므로 이 기계 밖에서는
닿지 않고, 계정도 외부 저장소도 필요 없다.

## 1. 신원을 둘로 가른다

**두 에이전트가 설정 파일을 공유하면 서로에게 말할 수 없다.** 봉인 대상은 나를 뺀 채널
멤버이므로, 같은 신원이면 상대가 목록에 없다. 그래서 각자 자기 설정 파일을 갖는다.

설정 경로는 `ACM_CONFIG` 로 정해진다. 클로드는 기본값(`~/.agent-channel-mesh/config.json`)을
그대로 쓰고, 코덱스만 다른 파일로 띄운다.

```bash
ACM_CONFIG=~/.agent-channel-mesh/codex.json codex
```

MCP 서버도 훅도 에이전트의 자식 프로세스라 이 값을 그대로 물려받는다. 매번 치기 싫으면
셸 프로필에 별칭을 둔다.

## 2. 릴레이를 띄운다

아무 세션에서나 한 번만 한다.

```
메시 설정 도와줘
```

스킬이 `relay_check` 로 이미 떠 있는지 보고, 없으면 띄우는 명령을 그대로 낸다. 세션이
백그라운드로 돌려도 되고 사용자가 붙여 넣어도 된다.

**릴레이는 세션보다 오래 살아야 한다.** 상대가 붙어 있는 동안 끊기면 그동안 온 메시지가
사라진다. 세션을 닫을 때 같이 죽는 자리에 두지 않는다.

## 3. 양쪽에 신원을 만든다

두 세션에서 각각 `메시 설정 도와줘` 라고 하고, 릴레이 주소로 `http://127.0.0.1:8787` 을 준다.
각 세션이 `setup` 으로 시드를 만들고(권한 600) 공개키와 지문을 낸다.

채널 비밀은 한쪽에서 만든 것 하나를 양쪽이 쓴다 — `setup` 이 만들어 보여준다.

## 4. 서로를 채널에 넣는다

`channel_join` 으로 같은 이름·같은 비밀의 채널에 각자 합류하면서, 상대의 `sign`·`kem`
공개키를 멤버로 넣는다. 축은 `internal` 이다.

## 5. 서로를 내 에이전트로 등록한다

`trust_agent` 에 **상대의 지문**을 넣는다. 이것이 설정의 `self` 이고, 여기 적힌 지문이 보낸
말만 제한 없이 돈다.

지문은 자르지 않고 전부 대조한다. 같은 기계라 화면에서 바로 비교할 수 있다.

## 6. 세션을 다시 연다

설정이 생겨도 이미 뜬 서버는 그대로다. 양쪽 세션을 다시 열면 메시 툴 네 개가 붙는다.

```
메시 채널에 누가 있는지 보여줘
```

`[내 에이전트]` 로 표시되면 끝난 것이다. 쓰는 법은 [주고받기](/guides/usage/).

## 자주 걸리는 곳

| 증상 | 원인 |
|---|---|
| 보냈는데 상대가 못 받는다 | 설정 파일을 공유하고 있다 — 1번을 안 했다 |
| 아무것도 안 온다 | 릴레이가 죽었다. `relay_check` 로 확인 |
| `[동료 공유]` 로 뜬다 | `trust_agent` 에 지문을 안 넣었거나 다른 지문을 넣었다 |
| 알림만 안 온다 | `/hooks` 승인을 안 했다 |
