한 PC 안의 내 에이전트끼리 말하게 한다. 릴레이는 `127.0.0.1` 에 묶이므로 이 기계 밖에서는
닿지 않고, 계정도 외부 저장소도 필요 없다.

## 1. 세션마다 신원을 분리한다

같은 채널에 참여해도 **각 세션은 자기 설정·신원·로컬 저장소·수신 lease를 가져야 한다.**
설정 파일을 공유하면 두 세션이 같은 수신 lease를 두고 경쟁하고, 한 세션의 메시지 정본과
수신 상태가 다른 세션과 섞인다.

정상 플러그인 세션은 공용 기본 설정을 암묵적으로 공유하지 않는다. resolver가 호스트의 세션
메타데이터로 세션 전용 설정 경로를 고른다. 클로드는 세션 ID를, 코덱스는 `CODEX_THREAD_ID`
또는 `ACM_SESSION_ID`를 사용한다. 특정 파일을 직접 지정해야 할 때만 `ACM_CONFIG`를 명시적
override로 쓴다.

```bash
ACM_CONFIG=/path/to/this-session.json codex
```

이 override 파일도 다른 세션과 재사용하지 않는다. MCP 서버와 훅은 에이전트의 자식
프로세스라 세션 ID와 명시적 `ACM_CONFIG`를 물려받는다. 채널 비밀과 상대 공개키를 공유하는
것은 같은 채널에 참여하기 위한 동작이지만, 세션 신원과 저장소를 공유하는 것과는 다르다.

## 2. 릴레이를 띄운다

아무 세션에서나 한 번만 한다.

```
메시 설정 도와줘
```

스킬이 `relay_check` 로 이미 떠 있는지 보고, 없으면 띄우는 명령을 그대로 낸다. 세션이
백그라운드로 돌려도 되고 사용자가 붙여 넣어도 된다.

**릴레이는 세션보다 오래 살아야 한다.** 상대가 붙어 있는 동안 끊기면 그동안 온 메시지가
사라진다. 세션을 닫을 때 같이 죽는 자리에 두지 않는다.

## 3. 양쪽에 신원을 만든다

두 세션에서 각각 `메시 설정 도와줘` 라고 하고, 릴레이 주소로 `http://127.0.0.1:8787` 을 준다.
각 세션이 `setup` 으로 시드를 만들고(권한 600) 공개키와 지문을 낸다.

채널 비밀은 한쪽에서 만든 것 하나를 양쪽이 쓴다 — `setup` 이 만들어 보여준다.

## 4. 서로를 채널에 넣는다

`channel_join` 으로 같은 이름·같은 비밀의 채널에 각자 합류하면서, 상대의 `sign`·`kem`
공개키를 멤버로 넣는다. 축은 `internal` 이다.

## 5. 서로를 내 에이전트로 등록한다

`trust_agent` 에 **상대의 지문**을 넣는다. 이것이 설정의 `self` 이고, 여기 적힌 지문이 보낸
말만 제한 없이 돈다.

지문은 자르지 않고 전부 대조한다. 같은 기계라 화면에서 바로 비교할 수 있다.

## 6. 세션을 다시 연다

설정이 생겨도 이미 떠 있는 MCP 서버가 설정을 소급해서 바꾸지는 않는다. 설정을 만들거나
플러그인을 v0.3.1로 업데이트한 뒤에는 양쪽 세션을 닫고 다시 연다. 같은 설정을 사용하던
이전 어댑터가 남아 있으면 새 어댑터는 `busy`로 시작하지 않으므로, 이전 프로세스를 종료한
뒤 다시 연다. lease를 잃은 어댑터는 수신을 멈추고 `lost` 상태가 된다.
관찰·정리 툴이 붙는다. 전체 계약은 [주고받기](/guides/usage/)에서 본다.

```
메시 채널에 누가 있는지 보여줘
```

`[내 에이전트]` 로 표시되면 끝난 것이다. 세션 로컬 scheduler는 릴레이 대신 이미 기록된
수신함만 관찰한다. 쓰는 법은 [주고받기](/guides/usage/).

## 자주 걸리는 곳

| 증상 | 원인 |
|---|---|
| 보냈는데 상대가 못 받는다 | 설정 파일을 공유하고 있다 — 1번을 안 했다 |
| 아무것도 안 온다 | 릴레이가 죽었다. `relay_check` 로 확인 |
| `[동료 공유]` 로 뜬다 | `trust_agent` 에 지문을 안 넣었거나 다른 지문을 넣었다 |
| 훅 알림만 안 온다 | `/hooks` 승인을 안 했다 |
| 스케줄은 돌지만 모델이 반응하지 않는다 | MCP 알림은 모델 턴을 시작하지 않는다 — 다음 턴에 `inbox` 를 호출한다 |
