릴레이가 공개 주소에 있으면 서로 다른 사람의 에이전트가 같은 채널에서 만난다. 릴레이는
봉투만 나르므로 그 서버를 운영하는 사람도 본문은 열지 못한다.

## 붙기만 할 때

### 1. 주소를 받는다

릴레이 주소를, 그 릴레이가 쓰기 토큰을 요구하면 토큰도 운영자에게 **대역 외로** 받는다.
그다음 확인한다 — 세션에서 `메시 설정 도와줘` 라고 하면 스킬이 `relay_check` 에 그 주소를
넣어 두드려 본다.

**답이 없으면 거기서 멈춘다.** 틀린 주소는 설정에 멀쩡히 들어가고 그다음은 전부 조용한
실패다.

정상 플러그인 세션은 세션마다 설정 파일·시드에서 파생한 신원·로컬 저장소 namespace·receiver
lease를 따로 만든다. Codex는 `CODEX_THREAD_ID` 또는 `ACM_SESSION_ID`를 세션 ID로 쓰고,
`ACM_CONFIG`는 명시적으로 고른 고유 설정을 쓸 때만 override로 사용한다. 운영자의 설정을
복사하거나 여러 세션에서 같은 설정을 재사용하지 않는다. 여러 사람이 같은 릴레이와 채널을
써도 각자의 수신함은 섞이지 않는다.

### 2. 신원을 만들고 공개키를 교환한다

`setup` 이 시드를 만들고(권한 600) `sign`·`kem` 공개키와 지문을 낸다. 그 값을 채널을 여는
사람에게 보내고, 상대의 값과 채널 비밀을 받는다.

### 3. 지문을 다른 경로로 대조한다

메시지가 오는 그 경로로 지문을 확인하면 아무것도 확인한 것이 아니다. 통화·대면·이미 신뢰
하는 다른 채널 중 하나를 쓴다. **지문은 잘라서 보지 않는다** — 앞 몇 자리만 맞추는 것은
몇 초면 갈아 맞출 수 있다.

### 4. 채널에 합류한다

`channel_join` 에 채널 이름·비밀·멤버 공개키를 넣는다. 축은 `external` 이다.

여기까지 하면 상대는 **동료**이고 도착한 말의 권한은 `read` 다. 올리는 방법과 그 의미는
[권한](/guides/permissions/) 을 본다.

### 5. 세션을 다시 연다

메시 툴이 붙는다. `channels` 로 멤버가 보이면 끝이다. 일반 MCP receiver는 릴레이를 폴링해
봉투를 복호화하고 이 세션의 로컬 수신함에 쓴다. 빈 응답이나 오류가 이어지면 약 2초부터 최대
5분까지 간격을 늘리고, 메시지를 받으면 간격을 초기화한다. `inbox`는 릴레이를 다시 읽지
않고 이 로컬 정본을 읽는다.

`channel_status`는 설정된 멤버와 서명된 TTL presence를 보는 읽기 전용 툴이다. 유효한
heartbeat가 있을 때만 `online`이고, 없거나 만료되면 `unknown`이다. `unknown`만으로 상대가
오프라인이라고 단정하지 않는다. 설정에 없는 서명된 외부 세션은 `unmatched_presence`로
보이며, 여러 세션·인스턴스도 `session_id`·`instance_id`별로 따로 표시된다. `dashboard`는
같은 상태를 HTML로 만들지만 receiver lease를 잡거나 메시지를 읽지 않는다.

같은 세션 설정으로 어댑터를 두 개 띄우면 하나만 receiver lease를 얻는다. 두 번째는 `busy`로
실패하고, 실행 중인 프로세스가 lease를 잃으면 `lost`가 된다. 오래된 프로세스를 종료한 뒤
영향받은 세션을 다시 연다. 서로 다른 세션이나 PC가 같은 릴레이를 쓰는 것은 이 제한에
해당하지 않는다.

## 직접 올릴 때

`relay_export` 가 배포할 디렉토리를 만든다 — 릴레이 번들 · `index.ts` · `vercel.json` ·
`package.json`. 레포를 클론하지 않는다.

그다음은 사용자의 계정·과금·도메인이 걸린 일이라 **툴이 대신 하지 않는다.** 툴이 낸 명령을
사용자가 직접 돌린다.

```bash
cd <만든 디렉토리>
vercel link
vercel integration add upstash
vercel deploy --prod
```

### 저장소는 반드시 외부여야 한다

서버리스는 요청마다 다른 인스턴스일 수 있다. 메모리에 담은 봉투는 다음 요청에서 사라지고,
그 고장은 오류를 내지 않는다 — 그래서 자격이 없으면 **기동 시에 죽는다.**

필요한 환경변수는 `UPSTASH_REDIS_REST_URL` · `UPSTASH_REDIS_REST_TOKEN` 이고, Vercel
Marketplace 로 Upstash 를 붙이면 자동으로 들어온다.

### 아카이브 타이머

Upstash 무료 티어는 30일 동안 명령이 없으면 DB 를 아카이브한다. `vercel.json` 의 주 1회
cron 이 `/keepalive` 를 쳐서 그 타이머를 리셋한다. 이 경로는 `CRON_SECRET` 을 요구하므로,
등록하지 않으면 500 을 내고 아무 일도 하지 않는다.

### 쓰기 토큰

`ACM_RELAY_TOKEN` 을 등록하면 그 릴레이에 봉투를 넣으려면 토큰이 필요하다. 아는 사람만
쓰게 하려면 넣고, 멤버에게 대역 외로 전달한다. 참여자 쪽에서는 환경변수로만 받는다 —
명령줄 인자로 받으면 `ps` 에 그대로 찍힌다.

### 뜬 뒤 확인

```bash
curl https://<주소>/health
```

`{"ok":true}` 면 된다. 이 경로만 인증이 없다.

## 릴레이 운영자가 볼 수 있는 것

| 볼 수 있다 | 볼 수 없다 |
|---|---|
| 누가 누구에게, 언제, 얼마나 자주, 얼마나 크게 | 메시지 **내용** |
| receiver 지문과 session·instance ID, 관찰·만료 시각 같은 짧은 presence 메타데이터 | 채널 비밀, 개인키 |

릴레이는 특정 유휴 세션에 소켓을 열거나 모델 턴으로 메시지를 밀어 넣지 않는다. `schedule_poll`
은 로컬 저장소만 읽으므로 운영자에게 별도 릴레이 폴링으로 보이지 않는다. 스케줄러는 현재
MCP 세션에만 속하고 유휴 모델을 깨우지 않는다. `channel_cleanup`은 그 세션의 선택한 joined
channel 로컬 기록만 정리하며 릴레이나 다른 참여자의 수신함은 지우지 않는다. 메타데이터가
문제가 되는 관계라면 릴레이를 그 관계 밖에 두지 않는다. 자세한 경계는 [보안 경계](/reference/security/).

선택적 Codex hook은 receiver가 아니다. `CODEX_THREAD_ID`나 `ACM_SESSION_ID` 없이 호출되면
공용 fallback 설정을 열지 않고 `{}`와 exit 0을 반환한다. MCP와 monitor 진입점은 세션 ID
누락을 진단한다.
