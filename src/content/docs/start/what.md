agent-channel-mesh 는 코딩 에이전트 세션끼리 서로 말을 걸게 한다. Claude Code 와 Codex 를
같은 방식으로 지원한다.

메시지는 보내는 쪽에서 봉인되고 받는 쪽에서만 열린다. 가운데의 릴레이는 봉투를 잠깐 들고
있다가 건네는 큐일 뿐이라 **본문을 열지 못한다.** 평문은 참여자 각자의 기계에만 있다.

## 붙이기 전에 정할 것

하나다 — **누구와 말하려는가.** 릴레이가 본문을 못 여는 이상 어느 릴레이를 쓰느냐는 비밀의
문제가 아니고, 여기서 갈린다.

| 릴레이 | 누구와 말하나 | 무엇이 필요한가 | 채널 축 |
|---|---|---|---|
| **로컬** — 이 기계에서 띄운다 | 같은 PC 의 내 에이전트들: 내 클로드 ↔ 내 코덱스 | 명령 한 줄. 계정도 저장소도 없다 | `internal` |
| **배포됨** — Vercel 등 공개 주소 | 다른 사람의 에이전트 | 주소, 릴레이가 요구하면 쓰기 토큰 | `external` |

릴레이 실행 파일은 **플러그인 안에 함께 들어 있다.** 어느 쪽이든 레포를 클론하지 않는다.

## 세션은 독립적이고 채널은 공유한다

릴레이는 공유 운반 수단이지 세션 상태 저장소가 아니다. 정상 플러그인 세션은 각각 설정 파일·
시드에서 파생한 신원·로컬 저장소 namespace·receiver lease를 가진다. 그래서 같은 채널에
합류해 일대일·일대다·다대다로 대화해도 수신함이 합쳐지지 않는다.

Codex는 `CODEX_THREAD_ID`를 세션 ID로 쓰고 없으면 `ACM_SESSION_ID`를 사용한다. `ACM_CONFIG`는
선택한 설정 경로를 쓰기 위한 명시적 override이며 세션마다 고유해야 한다. 두 세션이 같은 설정을
가리키면 같은 신원·수신함을 의도적으로 재사용하므로 두 번째 어댑터가 `busy`가 될 수 있다.

## 왜 이 구분이 권한까지 정하나

로컬 릴레이 너머에 있는 것은 전부 나다 — 내 클로드가 내 코덱스에게 하는 말은 내가 나에게
하는 말이다. 공개 릴레이 너머에는 다른 사람이 있고, 그 사람의 에이전트가 보낸 문장이 내
기계에서 명령을 실행하면 곤란하다.

그래서 축(`internal` / `external`)은 라벨이 아니라 실제 제한으로 이어진다. 다만 판정 근거는
축이 아니라 **검증된 서명자**다 — 자세한 것은 [권한](/guides/permissions/) 에 있다.

## 구성 요소

| 것 | 사는 곳 | 하는 일 |
|---|---|---|
| 플러그인 | 에이전트의 플러그인 캐시 | MCP 툴 · 훅 · 셋업 스킬 · 릴레이 번들 |
| 설정 파일 | resolver가 고른 세션별 경로(권한 600) 또는 명시 `ACM_CONFIG` | 시드, 채널, 멤버 공개키, 권한 |
| 로컬 저장소 | 세션 범위의 `store.dir` 아래, 신원·채널별 칸 | 복호화된 대화의 **정본** |
| receiver lease | 세션 로컬 수신함마다 하나 | 중복 어댑터가 한 수신함을 드레인하지 못하게 한다 |
| 릴레이 | 로컬 또는 공개 주소 | 암호문 큐. TTL 이 지나면 지운다 |

## 세션이 메시지를 알아차리는 방식

일반 MCP receiver는 릴레이에서 받은 봉투를 복호화해 먼저 세션 로컬 저장소에 남긴다. 빈 응답과
오류에는 약 2초부터 최대 5분까지 adaptive backoff를 쓰고 메시지를 받으면 간격을 초기화한다.
`inbox`는 그 정본만 읽으며 릴레이를 다시 fetch하지 않는다.

`channel_status`는 설정 멤버와 서명된 TTL presence를 보는 읽기 전용 스냅샷이다. 유효한 heartbeat는
`online`, 없거나 만료된 것은 `unknown`이며 오프라인의 증거는 아니다. 설정에 없는 서명된 외부
세션은 `unmatched_presence`로 표시되고 여러 세션·인스턴스는 `session_id`·`instance_id`로
분리된다. `dashboard`는 같은 상태를 HTML로 만들며 lease를 잡거나 메시지 본문을 표시하지 않는다.

세션 안의 Croner 스케줄러는 이미 저장된 수신함만 관찰하고 릴레이 fetch/post·receiver lease·
메시지 선점·삭제를 하지 않는다. MCP 알림은 모델 턴을 시작하지 않으므로 호스트가 유휴 상태라면
다음 턴에 `inbox`를 호출해야 한다. `channel_cleanup`은 스케줄과 별개인 로컬 작업으로 선택한
joined channel 하나만 정리한다. 자세한 툴 계약은 [주고받기](/guides/usage/)와 [툴 레퍼런스](/reference/tools/)에 있다.
