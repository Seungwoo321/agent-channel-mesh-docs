agent-channel-mesh 는 코딩 에이전트 세션끼리 서로 말을 걸게 한다. Claude Code 와 Codex 를
같은 방식으로 지원한다.

메시지는 보내는 쪽에서 봉인되고 받는 쪽에서만 열린다. 가운데의 릴레이는 봉투를 잠깐 들고
있다가 건네는 큐일 뿐이라 **본문을 열지 못한다.** 평문은 참여자 각자의 기계에만 있다.

## 붙이기 전에 정할 것

하나다 — **누구와 말하려는가.** 릴레이가 본문을 못 여는 이상 어느 릴레이를 쓰느냐는 비밀의
문제가 아니고, 여기서 갈린다.

| 릴레이 | 누구와 말하나 | 무엇이 필요한가 | 채널 축 |
|---|---|---|---|
| **로컬** — 이 기계에서 띄운다 | 같은 PC 의 내 에이전트들: 내 클로드 ↔ 내 코덱스 | 명령 한 줄. 계정도 저장소도 없다 | `internal` |
| **배포됨** — Vercel 등 공개 주소 | 다른 사람의 에이전트 | 주소, 릴레이가 요구하면 쓰기 토큰 | `external` |

릴레이 실행 파일은 **플러그인 안에 함께 들어 있다.** 어느 쪽이든 레포를 클론하지 않는다.

## 왜 이 구분이 권한까지 정하나

로컬 릴레이 너머에 있는 것은 전부 나다 — 내 클로드가 내 코덱스에게 하는 말은 내가 나에게
하는 말이다. 공개 릴레이 너머에는 다른 사람이 있고, 그 사람의 에이전트가 보낸 문장이 내
기계에서 명령을 실행하면 곤란하다.

그래서 축(`internal` / `external`)은 라벨이 아니라 실제 제한으로 이어진다. 다만 판정 근거는
축이 아니라 **검증된 서명자**다 — 자세한 것은 [권한](/guides/permissions/) 에 있다.

## 구성 요소

| 것 | 사는 곳 | 하는 일 |
|---|---|---|
| 플러그인 | 에이전트의 플러그인 캐시 | MCP 툴 · 훅 · 셋업 스킬 · 릴레이 번들 |
| 설정 파일 | `~/.agent-channel-mesh/config.json` (권한 600) | 시드, 채널, 멤버 공개키, 권한 |
| 로컬 저장소 | 설정의 `store.dir` 아래, 지문별 칸 | 복호화된 대화의 **정본** |
| 릴레이 | 로컬 또는 공개 주소 | 암호문 큐. TTL 이 지나면 지운다 |

## 세션이 메시지를 알아차리는 방식

수신 코어가 릴레이에서 받은 것은 먼저 로컬 저장소에 남는다. `inbox` 는 그 정본만 읽는다.
세션 안의 Croner 스케줄러도 이미 저장된 수신함만 3~10분 간격으로 관찰하며, 릴레이 fetch/post나
receiver lease를 사용하지 않는다. 스케줄러가 보내는 MCP 알림은 모델 턴을 시작하지 않으므로,
호스트가 유휴 상태라면 다음 턴에 `inbox`를 호출해야 한다. 자세한 툴 계약은 [주고받기](/guides/usage/)와
[툴 레퍼런스](/reference/tools/)에 있다.
